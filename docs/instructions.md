## 2. Environment Configuration (`.env`)

The project uses environment variables to isolate credentials and operational modes.

### Step 1: Copy Environment Template
```bash
cp .env.example .env
```

### Step 2: Key Environment Variables Explained
Below are the critical variables configured in `.env`:

| Variable | Default (Local Dev) | Purpose |
| :--- | :--- | :--- |
| `PROJECT_NAME` | `Freelancer Marketplace` | Application name used in emails and OpenAPI docs. |
| `DOMAIN` | `localhost` | Domain name for routing and CORS policies. |
| `ENVIRONMENT` | `local` | `local`, `staging`, or `production`. |
| `SECRET_KEY` | `CHANGEME_SECRET_KEY...` | Cryptographic key for signing JWT access tokens. |
| `POSTGRES_SERVER` | `db` | Database host container name. |
| `POSTGRES_PORT` | `5432` | PostgreSQL port. |
| `POSTGRES_DB` | `app` | Database name. |
| `POSTGRES_USER` | `postgres` | Database superuser username. |
| `POSTGRES_PASSWORD` | `changethis` | Database superuser password. |
| `FIRST_SUPERUSER` | `admin@example.com` | Initial admin account email generated at prestart. |
| `FIRST_SUPERUSER_PASSWORD` | `changethis` | Initial admin account password. |
| `REDIS_HOST` | `redis` | In-memory message broker host. |
| `REDIS_PORT` | `6379` | In-memory message broker port. |
| `CLOUDINARY_URL` | *(Optional in dev)* | Cloudinary credentials for media upload (`cloudinary://key:sec@cloud`). |
| `GOOGLE_CLIENT_ID` | *(Optional in dev)* | Google OAuth 2.0 Client ID for social login. |
| `LINKEDIN_CLIENT_ID`| *(Optional in dev)* | LinkedIn OIDC Client ID for social login. |

> ⚠️ **Important for Production:** In production, never commit real secrets. Production uses `compose.deploy.yml` with strict firewall rules and TLS certificates generated by Traefik.

## 3. Running the Project

### Option A: Complete Stack via Docker Compose (Recommended for 42 Evaluation)

This is the fastest, cleanest way to run the entire system with zero host dependencies other than Docker:

1. **Clone the repository:**
   ```bash
   git clone https://github.com/Moody-0x01/Freelancer.git
   cd Freelancer
   ```

2. **Prepare environment variables:**
   ```bash
   cp .env.example .env
   ```

3. **Launch all containers in the background:**
   ```bash
   make up
   # Or directly: docker compose up -d --build
   ```

4. **Initialize database schema & superuser:**
   ```bash
   docker compose run --rm backend bash scripts/prestart.sh
   ```

5. **(Optional) Seed mock users, jobs, and profiles:**
   ```bash
   make seed
   # Or: docker compose exec backend python app/seed_morocco_data.py
   ```

6. **Check running services:**
   ```bash
   make status
   ```

---

### Option B: Local Development Workflow (Hot-Reload)

This workflow runs PostgreSQL, Redis, and Mailpit inside Docker, while running the FastAPI backend and React frontend directly on your host for instant hot-reload:

1. **Start database and infrastructure services:**
   ```bash
   docker compose up -d db redis mailpit
   ```

2. **Run Backend (Terminal 1):**
   ```bash
   cd backend
   uv sync
   uv run bash scripts/prestart.sh
   uv run fastapi dev
   ```
   *Backend API runs at:* `http://localhost:8000`  
   *Interactive API Docs (Swagger UI):* `http://localhost:8000/docs`

3. **Run Frontend (Terminal 2):**
   ```bash
   cd frontend
   bun install
   bun run dev
   ```
   *Frontend dev server runs at:* `http://localhost:5173`

4. **Compile TypeScript Client after Backend Schema Changes:**
   ```bash
   bash ./scripts/generate-client.sh
   ```

## 5. Automated Tests & Code Quality

### Running Backend Unit & Integration Tests:
```bash
make test
# Or inside backend: cd backend && uv run bash scripts/test.sh
```
Runs 170+ tests covering endpoints, authentication, CRUD, and WebSockets, and outputs an HTML code coverage report at `backend/htmlcov/index.html`.

### Running Frontend Formatting & Typechecks:
```bash
cd frontend
bun run format    # Format codebase with Biome
bun run build     # Verify TypeScript types and compile production bundle
```

### Running the Disaster Recovery Sandbox Drill:
```bash
make dr-test
```
Executes an isolated disaster recovery drill in `< 5s`, spinning up an ephemeral container, restoring the latest compressed backup snapshot, validating table count, and tearing down cleanly.

## 6. Teardown & Clean-up

To stop and remove containers, networks, and volumes:
```bash
make down          # Stop containers
make clean         # Stop containers and prune temporary artifacts
docker compose down -v  # Stop containers and remove persistent database volumes
```
